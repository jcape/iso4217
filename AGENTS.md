# AGENTS.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```sh
cargo build --workspace --all-features
cargo clippy --workspace --all-features            # CI runs with RUSTFLAGS="-D warnings"
cargo fmt --all -- --check
cargo test --workspace --all-features
cargo test -p iso4217-static for_country           # single test by name filter
cargo test -p iso4217-parser counts::xml20260101   # yare-parameterized case
cargo nextest run --workspace --profile ci         # what CI uses (config in .config/nextest.toml)
cargo test --workspace --doc
cargo deny --all-features check                    # licenses, bans, advisories (deny.toml)
cargo +1.88 check --workspace --all-features       # MSRV
```

The `static` crate's features (`alloc`, `serde`, `zerocopy`) are built in CI across a matrix including `--no-default-features`; check the no-default-features build when touching `static`. Pre-commit hooks are managed by `prek` (`prek.toml`) and enforce Conventional Commit messages.

## Architecture

Three-crate workspace forming a codegen pipeline: **parser → macros → static**.

- **`parser`** (`iso4217-parser`): serde/quick-xml model of the ISO 4217 "List One" XML (`CurrencyDoc` → `CurrencyTable` → `CurrencyEntry` → `CurrencyName`). Fields use `#[serde(alias = ...)]` for the XML element names; accessors trim whitespace and normalize values (e.g. minor unit `"N.A."` → `None`). The publish date is parsed with `jiff`.
- **`macros`** (`iso4217-macros`): proc-macro `generate!(xml = "...", zerocopy = true|"feature")`. The `xml` path is resolved relative to the *calling crate's* `src/` dir via `CARGO_MANIFEST_DIR`. `xml/config.rs` parses the macro args; `xml/recordset.rs` (`EntrySet::from_entries`) turns entries into parallel vectors of idents/codes/numbers/etc.; `xml.rs` emits the `Error` enum, the `Currency` enum, and its `const fn` impl via `quote!`.
- **`static`** (`iso4217-static`, `no_std`): invokes `generate!` on `src/list-one.xml`, then hand-writes trait impls (`FromStr`, `TryFrom<u16|&str|iso3166 types>`, `Display`/`core::error::Error` for `Error`, serde in `serde.rs`). Most of the public API is therefore generated — look in `macros/src/xml.rs` for method definitions, not `static/src/lib.rs`.

Things that require reading across crates:

- **Identifier normalization lives in `recordset.rs`.** Currency names and country names are PascalCased with `heck` plus a chain of hard-coded `.replace(...)` fixups (non-ASCII, long official names, data errors like VED). Country idents must exactly match variant names in `iso3166-static` (`Numeric`/`Alpha2`/`Alpha3`), or the generated `from_*_country` matches fail to compile. Funds, `ZZ*` entries and `NON_COUNTRIES` are excluded from the country map. Updating `list-one.xml` usually means adding fixups here.
- Entries are deduplicated by numeric code (first wins after sorting by number), so a currency shared by many countries yields one enum variant.
- Generated code must satisfy the workspace's very strict clippy config (`[workspace.lints]` in the root `Cargo.toml`: `pedantic`, `missing_inline_in_public_items`, `missing_docs_in_private_items`, `absolute_paths`, `unwrap_used`, etc.), since it is linted as part of `static`. Use `#[expect(..., reason = ...)]`, not `#[allow]` (`allow_attributes` is denied).

## Conventions

- MSRV is 1.88 (`rust-version` in workspace `Cargo.toml`); edition 2024. The local toolchain is `stable`.
- All crates share one version (`shared-version = true`); releases and per-crate `CHANGELOG.md` files are generated by release-plz from Conventional Commit messages — don't hand-edit changelogs.
- `deny.toml` denies unused and duplicate workspace dependencies, and only allows Apache-2.0/MIT/Unicode-3.0 licenses.
- Import ordering (CONTRIBUTING.md): `extern crate`, then `pub use`, `pub mod`, `mod`, then `use`.
